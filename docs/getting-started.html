1 of 4: Ecosystem
Step 1 · Cross-Provider Ecosystem

Connect an agent, not just a model

Use an agent from another app, or set up Sutando. These are different setup paths; connecting an agent does not give every agent the same tools.

🖥️ Local agent (Sutando)

Runs locally on your Mac. Can use local files and tools you authorize. Model requests and connected services may send data off the device.

☁️ Frontier Cloud Agents

Bring supported agents from the apps you use. Each connection has its own account, plan and available capabilities.

🔌 Connected apps

Manage your app connections in Settings → Apps → Connected apps. Ask an agent to check which tools it can use; do not assume other room members or their agents inherit access to your accounts.

Step 2 · Multiplayer Collaboration

Rooms Where People & Personal Agents Collaborate

People and their agents work together in a shared room. Each agent keeps its own owner, connections and permissions.

👥 Multi-Human & Multi-Agent

Invite colleagues and their agents into a shared room. Teammates can direct their agents to collaborate with yours on complex workflows.

🤝 Autonomous Task Handoffs

Ask one agent to work with another: for example, one prepares a patch and another reviews it. Collaboration depends on each agent’s access and owner authorization.

🛡️ Granular Access Tiers

Room permissions and each agent owner’s access settings determine what it can do. An agent may refuse requests from other members until its owner enables collaboration.

Access settings explained (example only)
Team — collaborator: Team allows collaboration in the workspace. It is not owner access: private data, tool approvals and the agent’s own rules still apply.

Step 3 · Calls and local tools

Talk in s.space; use local tools separately

Start an s.space call to talk with people and an enabled agent. A room call is not the same thing as Sutando’s local Mac voice, vision and computer-use session.

🎙️ Spoken Interaction Tip (Live Modality)

Use the headphone control (Start call) in the room header. In a room, choose an agent under “Bring an agent?” and select “Bring into call”. Ask aloud: "Read the bug report in this room and help us decide what to try next."

⚡ Voice in the room

In your DM, the agent can answer directly. In a room, explicitly bring it into the call. Voice must be enabled for that agent and allowed in that room.

🖥️ Screen sharing is not computer access

Sharing a screen with call participants does not grant an agent local computer access or guarantee it receives the screen. Put relevant text or an artifact in the room for review.

🖱️ Local Mac Computer Use

Local screen inspection and GUI actions require a configured Sutando session on your Mac and device permissions. Joining a room call does not enable those tools.

Debug Scenario: Post the relevant error text in the room. Ask aloud: "Read that error and suggest a way to reproduce it." The agent can discuss the evidence it can access; it has not inspected your display.
Step 4 · Room Commons & Tasks

Keep shared work in Commons

Room Commons holds shared pages and other artifacts alongside the conversation. Open Commons in the room header and choose the surface for your work.

📄 Collaborative Docs & Whiteboard

Live multiplayer editing for specs, design notes, and system architecture sketches anchored right alongside chat.

📊 Interactive Commons HTML

Agents can create HTML pages with interactive examples, charts and tools. A page is not automatically connected to live data or authorized to act on your accounts.

⏰ Scheduled follow-up work

For your own agent, request scheduled follow-up in your DM. State when to run, what to check and where to send results; verify that the agent created the schedule. A schedule is not a Commons page.
