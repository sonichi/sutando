# GAIA-100 — 2026-08-26

Sutando answered 100 file-less GAIA validation cases. Scoring was **blind**: the answer key went
from the dataset into the suite on disk and never entered the agent's context; the harness scored
against it afterwards. Cases whose answers had previously been seen are excluded by ID
(`benchmarks/gaia-100.manifest.json`), so the run cannot be flattered by recall.

Reproduce the suite with `scripts/build-gaia-suite.py` and a local GAIA copy. The built suite is
gitignored — it carries the answer key, and committing it would contaminate GAIA for everyone.

## Result

| level | pass | rate |
|---|---|---|
| L1 | 30/34 | 88.2% |
| L2 | 40/55 | 72.7% |
| L3 | 6/11  | 54.5% |
| **all** | **76/100** | **76.0%** |

`COMPLETED` below means the case ran and produced an answer that did not match the key — a miss,
not an error. There were no non-responses.

## What the 24 misses say

They decompose cleanly, and the decomposition is more informative than the score. **No expected
answers appear below — categories and counts only, because publishing GAIA answers contaminates the
benchmark irreversibly.**

| category | n |
|---|---|
| declined — explicit `UNVERIFIED`, no guess | 13 |
| correct, scored wrong on case or punctuation | 4 |
| near-miss string (differs from the key by one transposed letter) | 1 |
| genuinely wrong answer | 6 |

### Strengths

**It does not fabricate, and that costs it points.** Thirteen of the misses are an explicit refusal
naming the obstacle — a bot challenge, a defunct domain, a paywalled source. Several of those cases
were guessable at odds well above chance, so a system tuned to score would have banked a few.
Refusing is a measurable sacrifice on a benchmark and the right behaviour in real work, where a
confident wrong answer costs more than an admitted gap.

**Single-hop is reliable: L1 88.2%.** Retrieval, reading, and one-step computation hold up.

**Four misses are correct answers** rejected on letter case or punctuation alone. On normalised
scoring this run is **80/100**.

### Weaknesses

**Tool and access reach is the dominant failure mode — 13 of 24**, more than reasoning errors and
formatting combined. That is plumbing, not intelligence.

**Multi-step numeric reasoning is the genuine weak spot — 6 real errors, and none are near-misses:**
each is off by an order of magnitude or more, not by a rounding step. This is the one category where
the refusal instinct does *not* engage — it declines when it cannot get data, but not when it has
data and mis-derives from it.

**L3 is 54.5%** — the deep chains are where both failure modes compound.

### The short version

It knows what it does not know and says so; it cannot reach half of what it needs; and when
arithmetic goes wrong it does not notice. The cheapest real gains are answer normalisation (4 points)
and tool access (13 blocked cases), not model work.
