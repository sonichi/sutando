# Sutando comprehensive benchmark — 2026-08-24

This report evaluates the installed Sutando desktop bundle as a personal AI
agent. It combines deterministic reliability checks with samples from three
public benchmarks. It is a private black-box evaluation, not a leaderboard
submission.

## Executive assessment

Sutando was strong on sampled research, constrained answering, and file
analysis once a task started. It scored **11/12 (91.7%)** on a deterministic
GAIA validation sample and answered all three selected attachment tasks
correctly. On nine matched file-less GAIA cases, performance moved from 7/9 in
the historical local run to 8/9 in this run. The aggregate improvement hides
two recovered cases and one new Level 3 regression.

The clearest weakness was workload isolation. A scheduled production
deployment occupied the single live core, and the first AssistantBench task was
not serviced within 600 seconds. The run was stopped and the pending campaign
tasks were removed from the live queue. This is direct evidence that a long
task can starve later user or evaluation work.

Long-context performance was mixed. Sutando returned all six sampled
LongMemEval oracle-context answers, but the official GPT-4o judge could not run
because the configured account had insufficient quota. Provisional diagnostics
were 33.3% normalized exact match, 50.0% gold-answer containment, and 0.629 mean
token-set F1. These diagnostics are not an official LongMemEval score.

The smoke run showed a warm-up effect: repetition-one median latency was about
25.7 seconds, versus 9.3 and 10.1 seconds for the next repetitions. GAIA Level
3 dominated the long tail. One research task took 378.0 seconds and its
attachment case took 250.8 seconds. Latency gates should therefore compare
within workload categories instead of using one global threshold.

## GAIA regression analysis

The sample contained three file-less questions and one attachment question
from each GAIA level. Selection was deterministic by task ID and the seed label
`sutando-20260824`; cases were not selected to maximize the result.

| Matched-task transition | Count |
|---|---:|
| Previous pass → current pass | 6 |
| Previous pass → current fail | 1 |
| Previous fail → current pass | 2 |
| Previous fail → current fail | 0 |

The matched sample improved by one net task, but the sample is too small for a
statistically reliable release-level claim. Per-task transitions remain
important: an aggregate-only gate would hide the new Level 3 regression.

For historical context, a July 2026 local campaign scored 103/127 (81.1%) on
file-less GAIA validation cases: Level 1 41/42, Level 2 53/66, and Level 3
9/19. That campaign used a different solver workflow, and one historical
answer carried a known contamination caveat. It is context, not a clean
baseline for this 12-task live-system sample.

## Long-term memory interpretation

The LongMemEval sample used the cleaned oracle dataset and selected one case
from every available question category:

- knowledge update;
- multi-session reasoning;
- single-session assistant memory;
- single-session preference;
- single-session user memory;
- temporal reasoning.

Relevant timestamped sessions were supplied in each isolated prompt. This
tests reasoning over provided episodic history. It does not test Sutando's own
ability to ingest conversations over time, retrieve them after restart, honor
deletion, update conflicting facts, or prevent cross-user leakage. Those need a
stateful adapter and isolated, resettable memory stores.

## Strengths exposed

1. The sampled GAIA accuracy was high, including all three attachments.
2. All 27 tasks that reached execution returned a response.
3. Narrow format and instruction constraints were followed consistently.
4. The matched GAIA set showed a small net improvement despite one regression.
5. The agent could reason over supplied multi-session history, although final
   correctness remains uncertain without the official judge.

## Weaknesses exposed

1. A long production task can starve later queue work for more than ten
   minutes; no workload isolation or preemption was observed.
2. GAIA Level 3 had both the only sampled correctness failure and extreme tail
   latency.
3. LongMemEval's provisional exact-match rate was only 33.3%.
4. The task bridge did not emit model tokens, tool calls, retries, active time,
   or estimated cost, preventing efficiency analysis.
5. Persistent personal memory, destructive-action safety, prompt injection,
   browser robustness, voice, desktop control, concurrency, crash recovery,
   multilingual behavior, and accessibility were not measured.
6. The installed package required retrospective version attribution; future
   runs should capture identity before and after the campaign in-band.

## Recommended release gates

These are initial internal gates and should be recalibrated after at least five
clean runs:

- Smoke: 100% over three repetitions and zero timeouts.
- Queue service: a dedicated benchmark task starts within 30 seconds; measure
  production contention separately.
- Matched GAIA: no aggregate decline and no new per-task regression without
  explicit review.
- GAIA attachments: at least 2/3 until the sample is expanded.
- Latency: compare p95 within a suite and category; warn on a greater than 20%
  regression only with adequate repeat count.
- LongMemEval: use the pinned official judge; never use heuristic diagnostics
  as a release gate.
- Public suites: keep official-protocol and adapted-protocol scores separate.

## Reproducibility and limitations

- The run used the live desktop core with its actual tools, browser state,
  skills, and memory. This improves ecological validity but allows background
  workload interference.
- GAIA validation data is gated and carries contamination risk. Task prompts,
  reference answers, raw responses, and private manifests are intentionally not
  committed with this public report.
- Samples are small regression sentinels and have no meaningful confidence
  interval. They are not public leaderboard estimates.
- Live web answers may change. Future AssistantBench runs should retain run
  date, input revision, and retrieved evidence.
- LongMemEval's official score remains pending; its provisional diagnostics
  must not be compared with published results.
- The report describes the installed revision `3a73e03`, not the benchmark CLI
  implementation in the PR that carries this report.

## Bottom line

Revision `3a73e03` demonstrates strong sampled research and attachment handling,
but it also exposes a product-level service weakness: a valid task can remain
unserviced for more than ten minutes behind unrelated work. The next campaign
should preserve this public-benchmark portfolio while adding a dedicated queue
lane, trace and cost telemetry, an official LongMemEval judge, and stateful
personal-memory and tool-calling adapters.
