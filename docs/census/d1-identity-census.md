# D1 identity/state census — Discord / AG2 Space / Slack

Strangler Slice 1 (read-only): the 7 delivery identities and 7 structural
facts of each chain's DM round trip, side by side, anchored to code. Generated
by `scripts/census-d1.py --write-doc`; `--verify` (run in CI) fails when an
anchor no longer matches the tree, so every cell stays checkable.

Slack caveat: the chain is configured-not-running on the reference host, so
its rows describe code, not observed behavior — it cannot serve as live
architecture evidence until its E2E environment is restored (Slice 5).

| dimension | discord | ag2space | slack |
|---|---|---|---|
| **provider event identity**| `message.id` from the gateway event; deduped only in-process (`seen_message_ids`, cleared at 10k) — not durable across restart _(src/discord-bridge.py)_ | broker task id from the gateway lease; Matrix `source_message_id` carried in the task header _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | Bolt Socket Mode event (SDK acks the envelope); the bridge records no event id of its own _(src/slack-bridge.py)_ |
| **normalized ingress identity**| none distinct — collapses into the freshly minted task id (event replay after restart = new task) _(src/discord-bridge.py)_ | `task-<inst>~<broker_id>` — injective mapping from the provider id, so a replayed lease maps to the same file _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | none distinct — collapses into the freshly minted task id _(src/slack-bridge.py)_ |
| **task_id**| `task-<epoch-ms>` minted by the bridge at write time (wall clock, not event-derived) _(src/discord-bridge.py)_ | `task-<inst>~<broker_id>` (provider-derived, per-instance collision-proof) _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | `task-<epoch-ms>` minted by the bridge _(src/slack-bridge.py)_ |
| **result publication identity**| `results/task-<id>.txt` mirrors the task id; bridge polls it back _(src/discord-bridge.py)_ | `results/task-<id>.txt`; body POSTed to the broker complete endpoint keyed by the broker id _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | `results/task-<id>.txt` polled by the watcher loop _(src/slack-bridge.py)_ |
| **delivery_id**| reply leg keyed by task_id in `pending_replies` (durable JSON); proactive leg is an outbox item in `.outbox-discord-proactive` _(src/discord-bridge.py)_ | broker task id on ack/complete; proactive posts carry an explicit `dedupe_key` _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | none stable — reply send is fire-and-forget; proactive keyed by result filename in `slack_proactive_receipts` _(src/slack-bridge.py)_ |
| **attempt_id**| proactive attempts durable in the outbox record; reply/marker leg counts attempts in-memory only _(src/discord-bridge.py)_ | no distinct attempt id — re-POST until 200 (at-least-once), in-flight set tracked in `remote-task-inflight*.json` _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | none — a failed send is retried by the next watcher poll pass _(src/slack-bridge.py)_ |
| **provider receipt**| `DeliveryReceipt` (CONFIRMED carries the provider message id) + append-only `outbox_log` _(src/discord-bridge.py)_ | gateway `event_id` when present; bare `ok` trusted as delivered; `record_delivered` via the vendored outbox _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | none persisted for replies (failures printed); proactive marked delivered in `slack_proactive_receipts` _(src/slack-bridge.py)_ |
| **process / entrypoint**| long-running discord.py gateway client, launched by startup.sh _(src/discord-bridge.py)_ | `src/remote-gateway-bridge.py` loader executing the vendored `ag2_sparrow.remote_gateway_bridge` long-poll loop _(src/remote-gateway-bridge.py)_ | `slack_bolt` SocketModeHandler process _(src/slack-bridge.py)_ |
| **durable state**| pending-replies JSON, `.outbox-discord-proactive`, `.sending` sentinels, tasks/ results/ processed/ _(src/discord-bridge.py)_ | `remote-task-inflight*.json`, `remote-task-rooms*.json`, `remote-dedup-alias*.json`, `results/undelivered/` _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | `slack_proactive_receipts` store + tasks/ results/ _(src/slack-bridge.py)_ |
| **direct network calls**| provider I/O behind `channels/discord`; plus a localhost agent-api `/task-done` POST _(src/discord-bridge.py)_ | REMOTE_TASK_URL REST in-module — that surface IS the provider edge _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | `app.client.chat_postMessage` called directly from bridge code at multiple sites (the direct outbound Slice 5 strangles) _(src/slack-bridge.py)_ |
| **private retry / receipt**| in-memory attempt counter on the marker leg; the proactive leg already rides the outbox-backed fence _(src/discord-bridge.py)_ | closest to canon: vendored outbox `classify_response` three-state + `record_delivered` _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | private `slack_proactive_receipts` + bare poll-loop retry _(src/slack-bridge.py)_ |
| **completion decision**| result file + marker parse -> deliver -> archive; also POSTs `/task-done` so the web UI flips _(src/discord-bridge.py)_ | result POST to `/v1/results` answered 200 -> archive (delivery completion and task completion conflated at the 200) _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | result file consumed -> post -> archive _(src/slack-bridge.py)_ |
| **restart recovery**| orphan `.sending` sweep before the poll + pending_replies reload from JSON _(src/discord-bridge.py)_ | in-flight JSON reload + gateway re-enroll claim _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | re-poll of results/; proactive receipts consulted before re-send (`was_delivered`) _(src/slack-bridge.py)_ |
| **credentials owner**| `resolve_channel_token("DISCORD_BOT_TOKEN")` over channels/discord/.env _(src/discord-bridge.py)_ | REMOTE_TASK_TOKEN via the ag2space channel env _(packages/ag2-sparrow/ag2_sparrow/remote_gateway_bridge.py)_ | SLACK_BOT_TOKEN / SLACK_APP_TOKEN: env -> channel .env -> vault _(src/slack-bridge.py)_ |
