# holder_lock: one-process exclusion per work root (parent PR, design v5.1)

Reviewed first; merged first. One module, `src/holder_lock.py`, vendored byte-identical into the package. v5 narrows the primitive to exactly what the three production adapters need: at most one owner process per work root, proven by a flock held for that process's whole life, with a holder record that says who. Child processes, orphans, fencing and signals are not this module's concern; the notifier PR solves them by parent-death propagation (its note), not by records. Test class: `HL` = `tests/holder-lock.test.py::HolderLockTest`, parametrised over the source and the vendored copy.

## What v5 moved to the notifier PR and why

- `children[*]`, `set_children`, reserve-then-spawn, the pending TTL: a record of children either wedges every successor behind a live orphan or releases it while the orphan still acts (the reviewer's findings 1, 2, 5). The notifier makes its children die with it instead, so there is nothing to record.
- Every fence and orphan rule, `authorize_signal` in all forms: signals are the consumer's; with no orphans there is nothing for this module to authorise (finding 6). A record here never names anything but its holder.
- The control-pipe protocol, the watcher and sender lifecycle, `status`'s child liveness: #5629's, specified executably there (finding 7).
- The notifier consumer paragraph: replaced by one sentence in §2 — the notifier publishes a holder record like any adapter.

## 1. API

1. `acquire(work_root, *, install_id, timeout=0.0) -> Acquired | Held | Contended | TimedOut | Unreadable | LegacyRunning`. In this order: `os.makedirs(work_root, exist_ok=True)` — the root itself is the ONLY thing created under or at the root before `Acquired`; `root = realpath(work_root)`; `lock_dir(root)` (§5.1) created `0700` if absent; `open(<lock dir>/lock, O_RDWR|O_CREAT|O_NOFOLLOW)`; `file_lock.try_lock_fd` — False → unlock nothing, close, `Contended(holder)` where `holder = read_holder(root)` as it is now (`Missing` while the winner is between its flock and its publish; a `wait` polls through it); True → `same_file` (else `LockError("replaced")`), then the root is revalidated: `lstat(work_root)` is a directory and not a symlink and `realpath(work_root) == root`, else unlock, close, `LockError("root changed")`. Then the prior is read under the flock and decides: `Missing` → `Acquired`; `Valid` with `verify_lineage(pid, start, host)` False → `Acquired` (overwritten on publish); True → unlock, `Held(holder, reason="live holder")`; None → unlock, `Held(holder, reason="unobserved")`; `Invalid` containing any parseable positive pid whose lineage is True or None → unlock, `Held(holder, reason="invalid record naming a live or unobserved pid")`; `Invalid` otherwise → `Acquired` (overwritten on publish); an `OSError` reading it → unlock, `Unreadable(reason)`. `LegacyRunning`: §4.3. `Acquired(owner, prior)`: `owner` is an in-process handle (fd with `FD_CLOEXEC`, `lock_id=(dev, ino)`, `pid`, `start`), never passed to a child, one per process (`LockError("already owner")` otherwise). Pins: `HL::test_acquire_publishes_nothing_and_returns_the_prior_under_the_flock`, `HL::test_a_live_or_unobserved_holder_is_held_and_a_dead_one_is_overwritten`, `HL::test_an_invalid_record_refuses_on_a_live_or_unobserved_pid_and_is_overwritten_otherwise`, `HL::test_a_loser_gets_contended_with_the_current_record_or_missing_while_the_winner_is_pre_publish`, `HL::test_a_replaced_lock_file_or_a_changed_root_is_refused`, `HL::test_one_owner_per_process`.
2. `wait(work_root, *, install_id, deadline, poll=0.1, on_tick=None) -> Acquired | TimedOut | Unreadable | LegacyRunning`: the loop over `acquire` for `Contended` and `Held`; `deadline` absolute `time.monotonic()`; `on_tick(elapsed_s, holder)` once per poll, may raise to abandon. The waiter writes `<lock dir>/waiting.<pid>` (`"<start> <epoch>\n"`, temp + rename) and removes it on return; a second `wait` in the same process while one is active raises `LockError("already waiting")` (same-process overlap is refused, not merged); readers ignore a file whose pid is dead or whose `start` differs from the pid's. Pins: `HL::test_each_waiter_owns_its_own_file_and_a_newer_waiter_exiting_first_leaves_the_older_visible`, `HL::test_same_process_overlapping_waits_are_refused`, `HL::test_wait_calls_on_tick_and_honours_an_absolute_deadline`.
3. `publish(owner, adapter) -> Published(record)`: once per owner (`LockError("published")` on a second call); verifies the owner is unreleased, `same_file(owner.fd, lock path)` and `lock_id`; writes `<lock dir>/holder` (§2) by unique dot-temp + fsync + `os.replace`, overwriting any prior; failure raises `LockError`, nothing written, the owner still valid. There is no other mutation of the record: the ownership questions of finding 5 reduce to this one write and the one removal in §1.4 — no `set_children` to race a replaced path, no fence for a cleanup path to erase. Pins: `HL::test_publish_is_once_per_owner_and_fills_every_field`, `HL::test_publish_overwrites_any_prior_and_leaves_no_temp`, `HL::test_publish_refuses_a_released_owner_a_closed_fd_or_a_replaced_file`.
4. `release(owner) -> Released(record_removed: bool)`: owner process only (`LockError("not the owner")` from any other pid, nothing touched — a forked child cannot release); removes `holder` only if `same_file` holds and the record on disk names this `pid`, `start` and `lock_id` (a record that names someone else is left byte-for-byte and `record_removed` is False); then unlocks and closes; single use (`LockError("released")`). The lock file is never unlinked, truncated, renamed or replaced by any function here. Pins: `HL::test_release_removes_only_its_own_record_then_unlocks_and_is_single_use`, `HL::test_release_from_a_forked_child_is_refused_and_the_parents_lock_stays`, `HL::test_nothing_in_the_module_unlinks_or_replaces_the_lock_file`.
5. `read_holder(work_root) -> Missing | Valid(record) | Invalid(reason, raw_bytes)`: never raises; `Invalid` for missing fields, wrong types or bounds, unsupported `schema`, torn JSON, a non-object. No caller may read `Missing` or `Invalid` as "free": the flock decides. Pin: `HL::test_read_holder_never_raises_and_classifies_every_malformed_shape`.
6. `same_file(fd, path) -> bool`; `verify_lineage(pid, start, host=None) -> bool | None` (None = unobserved, never a default); `start_time(pid) -> str | None` (`ps -o lstart=`, C locale, UTC, normalised); `install_id() -> str` (§4.1); `lock_dir(root) -> str` (§5.1); `status(work_root) -> dict` (the record, its holder's liveness, live waiters, a legacy `connector.pid` finding; read-only, never under the flock). Pins: `HL::test_same_file_rejects_a_replaced_or_missing_path`, `HL::test_verify_lineage_is_tri_state_and_rejects_a_recycled_pid`, `HL::test_start_time_ignores_locale_and_time_zone`, `HL::test_status_is_read_only_and_reports_an_invalid_record_stale_waiters_and_a_legacy_pidfile`.
7. Platform and `file_lock.py`: `holder_lock` builds on `file_lock` and this PR adds one typed function there, `try_lock_fd(fd) -> bool` (`EWOULDBLOCK` mapped once, in `file_lock`, which stays cross-platform); it does not use `locked_file`. The compatibility decision, recorded here and reflected in the package README and the `pyproject` classifiers: `holder_lock` and its four consumers (the three adapters, the notifier) are POSIX-only — Linux in CI, macOS by the manual witness; on Windows every entry point raises `LockError("unsupported platform: holder_lock is POSIX-only")` at first use, executed by the Windows job when it runs (label-gated; not a merge gate), not only mocked. Pins: `HL::test_holder_lock_locks_only_through_file_lock`, `tests/file-lock.test.py::test_try_lock_fd_returns_busy_instead_of_raising`, `HL::test_on_windows_every_entry_point_raises_lock_error` (real on the Windows job; mocked elsewhere).

## 2. Holder record

1. `<lock dir>/holder`, JSON, every field generated by `publish` except `adapter`: `{"schema": 1, "adapter": str, "pid": int, "start": str, "host": str, "install_id": str, "lock": {"dev": int, "ino": int}, "acquired_at": float}`. Nothing else: no children, no extra. The notifier publishes one like any adapter (`adapter: "codex-notifier"`).
2. Validation: `pid`, `dev`, `ino` are `int` and not `bool`, `pid > 0`; `start`, `host`, `adapter`, `install_id` non-empty `str` ≤ 512 bytes; `acquired_at` a finite `float`; unknown keys make it `Invalid`. Pin: `HL::test_record_field_types_and_bounds_are_enforced_on_read_and_publish`.
3. A record never authorises acquisition and never names a target for a signal; it says who holds, for `Held`'s explanation and `status`. Pin: `HL::test_no_code_path_reads_a_record_to_decide_acquisition` (spy).

## 3. Work root and first act

1. Nothing under the root except the root itself is created before `Acquired`: `acquire`'s `makedirs` of the root, then the lock dir and lock file outside it (§5.1), then the `waiting.<pid>` file during a `wait`. After `Acquired` the caller creates its own directories. Pins: `HL::test_only_the_root_itself_exists_under_the_root_before_acquired`, `HL::test_two_spellings_of_a_not_yet_existing_root_share_one_key` (`./w` and `x/../w` and a trailing slash, all absent, both acquire on one lock dir; the second is `Contended`/`Held`).
2. The symlink schedule from finding 4 is closed by the order in §1.1: the root is created before it is resolved, and revalidated after the flock; a root that became a symlink, or whose realpath changed, between those points is `LockError("root changed")` and the caller starts over. Pin: `HL::test_a_root_swapped_for_a_symlink_between_mkdir_and_flock_is_refused`.
3. "No trace" after any refusal (`Held`, `Contended`, `TimedOut`, `Unreadable`, `LegacyRunning`, `LockError`, or a fault between the flock and the return): under the root only the root itself exists beyond what was there; in the lock dir only the lock file and other processes' waiter files; the record is byte-identical. Pin: `HL::test_every_refusal_path_leaves_the_root_and_the_record_byte_identical`.
4. `tests/holder_lock_contract.py::FirstActContract`: a mixin driving a consumer's CLI argv through contention, no-trace, a missing root, a replaced lock file, the legacy refusal (§4.3), and publish-before-spawn — between `acquire` and `publish` the caller starts no child process (a read-only `ps` is not one). The parent runs it against a stub; each consumer subclasses it per caller. Pins: `HL::test_the_first_act_contract_passes_against_the_stub_caller`, `HL::test_the_first_act_contract_pins_publish_before_any_child_is_spawned`.

## 4. Install boundary and merge graph

1. `install_id()` is the install location only: `"<distribution>@<realpath of the package directory>"`; the notifier's is `"sutando-src@<realpath of src/>"`. Recorded for `status` and `Held`'s explanation; never compared on the acquire path (a same-location upgrade is a same-install predecessor; a different location that is live is simply `Held`). Pin: `HL::test_install_id_is_the_location_only_and_is_not_compared_on_acquire`.
2. The upgrade order is stop → install → start, owned by the upgrader. Merge graph: this prerequisite → #5660 (the three adapters as thin owners; its second commit also gives `ag2-sparrow-hatch install` and the package installer script their stop-the-package's-adapters → install → start, since the adapters' launch code lives there) → #5665 (rebases on #5660; its keepawake self-upgrade is re-ordered to stop → install → start and is the only unattended upgrader) → #5629. Each of those PRs pins its own order with `test_the_upgrader_stops_then_installs_then_starts`; here only `HL::test_a_start_against_a_live_holder_is_held_and_explains`.
3. Until the upgraders land, one refuse-and-explain at start, no runtime coexistence: after the flock and the prior read, `acquire` reads `<root>/state/connector.pid` ONCE. A single positive integer naming a pid whose lineage is True or None → unlock, `LegacyRunning(pid, path)`; the caller exits 3 "stop the old adapter (pid N), then start"; empty or malformed → refuse the same way with `pid=None` and "… and remove <path>" ONLY while the file is fresh — its mtime within the old writer's create-to-write window, 30 s (an empty file may be the old writer between its `O_EXCL` and its write); an empty or malformed file older than that is a crash leftover and is treated like a dead pid (ignored, never refused — otherwise every unattended start would refuse until a human deleted it); absent or a dead pid → proceed; `status` names whatever it finds and WARNS on a stale empty or malformed file. The file is never written or removed by this module; #5660's fresh-dir rule tolerates and removes an attributed dead one. This clause is deleted in the release after #5665 lands. Pins: `HL::test_a_live_or_unobserved_legacy_pid_refuses_and_explains`, `HL::test_a_fresh_empty_or_malformed_legacy_file_refuses_and_a_dead_or_absent_one_is_ignored`, `HL::test_a_stale_empty_or_malformed_legacy_file_is_ignored_and_status_warns` (mtime set 31 s back; the fresh case at 0 s), `HL::test_the_module_never_writes_or_removes_the_legacy_file`.
4. Out of contract, stated: an old writer started by hand after that one read, on a root the upgrader does not know, is not detected; the upgrade order is the control, `status` is the report.

## 5. Lock location and filesystem

1. `lock_dir(root)` is a function of the root's realpath and the uid ONLY: `<home of the effective uid, from pwd, not $HOME>/.local/state/ag2-sparrow/locks/<sha256(root)[:16]>`; no environment variable takes part, because a systemd unit, cron, a Hatch hook and a `nohup` shell differ and two adapters that resolved different dirs would both run. Files: `lock`, `holder`, `waiting.<pid>`. A root that contains its own lock dir (`--work=<that home>` or above it) is refused, `LockError("work root contains the lock directory")`. This is one deliberate amendment to the two-space workspace contract: a host-local, per-uid, never-synced runtime directory for locks, recorded in `docs/workspace-design.md` by this PR; it is not a third state container for anything else. Pins: `HL::test_lock_dir_is_a_function_of_realpath_and_uid_only_and_ignores_every_env_var`, `HL::test_two_launch_contexts_with_different_environments_resolve_one_lock_dir`, `HL::test_a_root_containing_the_lock_dir_is_refused`.
2. Local filesystem only: `acquire` raises `LockError("not a local filesystem")` when `statfs` reports a network or FUSE type for the lock dir (a network-mounted home); the package README and the adapters' READMEs state the refusal and the remedy (a local home for the service user). Pins: `HL::test_a_network_or_fuse_lock_dir_is_refused` (mocked statfs), `HL::test_the_readmes_document_the_network_home_refusal`.

## 6. Crash matrix (the owner killed at the boundary's end; the next start is the successor)

| After | Lock | Record | Successor |
|---|---|---|---|
| root mkdir, before flock | nobody | prior | reads prior; by its holder's liveness |
| flock, before the prior read | kernel dropped | prior | same; the read is repeatable |
| prior read, before publish | dropped | prior | same; a concurrent loser saw `Contended(prior)` and polls |
| record temp written | dropped | prior + dot-temp | publish overwrites; the temp is removed by `publish` |
| published | dropped | ours (dead pid) | dead → `Acquired`, `prior = Valid(ours)` |
| serving | dropped | ours | same |
| clean exit, record removed, before close | held until close | none | `Contended(Missing)` for an instant, then `Acquired` |

Pin: `HL::test_an_owner_killed_at_every_boundary_is_replaced_by_a_successor_whose_outcome_matches_the_row`.
