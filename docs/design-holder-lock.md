# holder_lock: the one flock-and-holder primitive (parent PR, design v4, simplified)

Reviewed first; merged first. One module, `src/holder_lock.py`, vendored byte-identical into the package; the two consumer PRs are thin owners over it. v4 cuts scope so that the first reviewer's v3.3 findings fall away instead of being patched: one long-lived owner process holds the flock for its whole life, no descriptor is ever shared or re-entered, the outlive-fence is carried by the record, the lock artifacts live outside the synced workspace, and the upgrader owns the upgrade order. Test class: `HL` = `tests/holder-lock.test.py::HolderLockTest`, parametrised over the source and the vendored copy.

## What v4 removed and why

- `lease_from_inherited_fd`, `check-held`, and every inherited-fd re-entry: no construction from a descriptor can prove that descriptor owns the flock (the reviewer's A/B/C counterexample), so no child ever holds or presents the fd.
- Helper republishing of `extra`, the fork guard, the minting-pid rule: with one owner process there is no second writer to guard against.
- `authorize_signal` taking a caller-supplied `{pid, start}`: a target not read from the authenticated record cannot be bound to it; targets are now named selectors into the record.
- `ForeignInstall`, `Inconsistent`, process-location inference, `check-install` at install time, the legacy pidfile read and every runtime legacy path: the upgrader's stop → install → start order is the control; the lock contract no longer tries to detect a violated order.
- `vault.sync.exclude` patterns and the sync-defaults test: the lock, holder and waiter files are no longer under the work root or the workspace, so nothing about sync applies.
- Archival of an invalid record (`.holder.invalid.<n>`): an invalid record is reported and left alone until a publish overwrites it; no second artifact to crash between.
- The single `.waiting` file with a nonce: one `waiting.<pid>` per waiter, removed by that pid.
- The diagnostic `version` field, the Windows CI claim, the "two CI runners" claim: `schema: 1` only; POSIX; Linux in CI, macOS by the manual witness, Windows a tested-nowhere `LockError`.

## 1. API

1. `acquire(work_root, *, install_id, timeout=0.0) -> Acquired | Held | TimedOut | Unreadable`. Resolves the lock directory (§5.1), creates it (mode 0700) if absent, opens `<lock dir>/lock` with `O_RDWR|O_CREAT|O_NOFOLLOW`, takes `LOCK_EX` through `file_lock.try_lock_fd`, then checks `same_file` (a replaced lock file is `LockError("replaced")`, unlock, close). Under the flock it reads the prior record (§1.5) and decides: `Missing` → `Acquired`; `Valid` whose every named pid (the holder and every `children[*]` entry with a pid) has `verify_lineage` False, and whose every pending slot is older than `PENDING_TTL_S = 30` → `Acquired`; any named pid with lineage True → unlock, `Held(holder, reason="holder"|"child:<name>")`; any lineage None → unlock, `Held(holder, reason="unobserved")`; `Invalid` that contains any parseable pid with lineage True → unlock, `Held(holder, reason="invalid record naming a live pid")`; `Invalid` with no live pid → `Acquired` (publish will overwrite it); a record that cannot be read at all (`OSError`) → unlock, `Unreadable(reason)`. `Acquired(owner, prior)`: `owner` is an in-process handle (fd with `FD_CLOEXEC`, `lock_id=(dev, ino)`, `generation = prior generation + 1 or 1`, `pid`), never passed to a child, one per process (`acquire` while already owning raises `LockError("already owner")`); `prior` is the exact `Prior` read under the flock. `TimedOut(holder)` only from `wait`. Nothing is written before `Acquired` except the lock dir and lock file (§3). Pins: `HL::test_acquire_publishes_nothing_and_returns_the_prior_under_the_flock`, `HL::test_a_prior_is_dead_only_when_the_holder_and_every_child_are_dead`, `HL::test_a_live_child_in_the_prior_holds_the_successor_off`, `HL::test_a_pending_slot_is_live_until_its_ttl_then_dead`, `HL::test_an_unobserved_lineage_or_unreadable_record_refuses_and_explains`, `HL::test_an_invalid_record_with_a_live_pid_refuses_and_without_one_is_overwritten`, `HL::test_a_replaced_lock_file_is_refused`, `HL::test_one_owner_per_process`.
2. `wait(work_root, *, install_id, deadline, poll=0.1, on_tick=None) -> Acquired | TimedOut | Unreadable`: the loop behind `timeout > 0`; `deadline` is absolute `time.monotonic()`; `on_tick(elapsed_s, holder)` once per poll, may raise to abandon. Each waiter writes `<lock dir>/waiting.<pid>` (`"<epoch>\n"`, temp + rename) and removes its own on return; readers (`status`, a health check) ignore a `waiting.<pid>` whose pid is dead. Two overlapping waiters never touch each other's file. Pins: `HL::test_each_waiter_owns_its_own_file_and_a_newer_waiter_exiting_first_leaves_the_older_visible`, `HL::test_wait_calls_on_tick_and_honours_an_absolute_deadline`.
3. `publish(owner, record) -> Published(record)`: once per owner (`LockError("published")` on a second call); verifies the owner is unreleased and `same_file(owner.fd, lock path)`; fills `schema`, `pid`, `start`, `host`, `lock`, `generation`, `install_id`, `acquired_at`, `children: []`; validates `adapter` and `extra` (§2.2); writes `<lock dir>/holder` by unique dot-temp + fsync + `os.replace`, overwriting whatever was there. Failure raises `LockError`, nothing written, the owner still valid. Pins: `HL::test_publish_is_once_per_owner_and_fills_identity_fields`, `HL::test_publish_overwrites_any_prior_and_leaves_no_temp`.
4. `set_children(owner, children) -> Published(record)`: the only mutation after publish, by the owner process only (`os.getpid() == owner.pid`, else `LockError("not the owner")`); replaces the `children` list atomically (same temp + replace), serialised in-process by the owner handle; `extra` and every other field are unchanged. A child slot is `{"name": str, "pending": bool, "reserved_at": float, "pid": int?, "start": str?}`. Pins: `HL::test_set_children_replaces_the_list_atomically_and_only_from_the_owner_pid`, `HL::test_set_children_from_a_forked_child_is_refused_and_the_record_is_unchanged` (real `os.fork`).
5. `read_holder(work_root) -> Prior`: `Missing | Valid(record) | Invalid(reason, raw_bytes)`; `Invalid` for missing fields, wrong types or bounds, unsupported `schema`, torn JSON, a non-object. It never raises; an `OSError` is surfaced by `acquire` as `Unreadable`. No caller may read `Missing` or `Invalid` as "free": the flock decides acquisition; the record decides only who is still alive and what may be signalled. Pin: `HL::test_read_holder_never_raises_and_classifies_every_malformed_shape`.
6. `release(owner) -> Released(record_removed: bool)`: owner process only (`LockError("not the owner")` otherwise, nothing touched); removes `holder` only if `same_file` holds and the record on disk names this `pid`, `generation` and `lock_id`; then unlocks and closes; the handle is dead and a second call raises `LockError("released")`. The lock file is never unlinked, truncated, renamed or replaced by any function here. Pins: `HL::test_release_removes_only_its_own_record_then_unlocks_and_is_single_use`, `HL::test_release_from_a_forked_child_is_refused_and_the_parents_lock_stays`, `HL::test_nothing_in_the_module_unlinks_or_replaces_the_lock_file`.
7. `authorize_signal(record, target, *, lock_id, install_id, argv_predicate=None) -> Authorized(pid, start) | Denied(reason)`: `record` is a `Valid` record the caller obtained from `Acquired.prior` or its own `publish`/`set_children` result; `target` is a selector, `"holder"` or `"child:<name>"`, resolved INSIDE the function from that record — a caller can never supply a pid. Authorised only when: `schema` supported; `record.host` equals the local host label; `record.lock` equals `lock_id` (the caller's own); `record.install_id` equals `install_id`; the selected slot is not pending; `verify_lineage(pid, start, host)` is True; and, when given, `argv_predicate(live argv of pid)` is True. Denial reasons are distinct and none means "gone" except `gone`: `no-such-target`, `pending`, `foreign-host`, `foreign-install`, `wrong-lock`, `unobserved`, `recycled`, `gone`, `argv`. Pins: `HL::test_authorize_signal_resolves_the_target_from_the_record_and_never_from_the_caller` (A-record/B-process substitution is impossible by construction and pinned by a B-pid that is never consulted), `HL::test_each_denial_reason_is_distinct_and_only_gone_means_gone`.
8. `same_file(fd, path) -> bool`; `verify_lineage(pid, start, host=None) -> bool | None` (None = unobserved, never a default); `start_time(pid) -> str | None` (`ps -o lstart=`, C locale, UTC, normalised); `install_id() -> str` (§4.1); `lock_dir(work_root) -> str` (§5.1); `status(work_root) -> dict` (the prior, its liveness per slot, live waiters; read-only). Pins: `HL::test_same_file_rejects_a_replaced_or_missing_path`, `HL::test_verify_lineage_is_tri_state_and_rejects_a_recycled_pid`, `HL::test_start_time_ignores_locale_and_time_zone`, `HL::test_status_is_read_only_and_reports_an_invalid_record_and_stale_waiters`.
9. Platform and `file_lock.py`: `holder_lock` builds on `file_lock` and this PR adds one typed function there, `try_lock_fd(fd) -> bool` (True acquired, False busy; `EWOULDBLOCK` mapped once, in `file_lock`); it does not use `locked_file`. The contract is POSIX: tested on Linux in CI; macOS by the manual live witness at the consumer heads; on Windows every entry point raises `LockError("unsupported platform: holder_lock is POSIX-only")` at first use, and no CI job is claimed for it. This narrows the adapters that call it to POSIX, stated in their READMEs. Pins: `HL::test_holder_lock_locks_only_through_file_lock`, `tests/file-lock.test.py::test_try_lock_fd_returns_busy_instead_of_raising`, `HL::test_on_an_unsupported_platform_every_entry_point_raises_lock_error` (mocked `file_lock.fcntl is None`).

## 2. Holder record

1. `<lock dir>/holder`, JSON: `{"schema": 1, "adapter": str, "pid": int, "start": str, "host": str, "lock": {"dev": int, "ino": int}, "generation": int, "install_id": str, "acquired_at": float, "children": [slot...], "extra": object}`; `slot` as in §1.4. Every field is generated or defaulted by `publish` except `adapter` and `extra`; `extra` defaults to `{}`.
2. Validation: `pid`, `dev`, `ino`, `generation` are `int` and not `bool`, `pid > 0`, `generation >= 1`; `start`, `host`, `adapter`, `install_id`, `name` are non-empty `str` ≤ 512 bytes; `acquired_at`, `reserved_at` are finite `float`; `children` has ≤ 64 slots with unique names; `extra` is a JSON object ≤ 64 KiB. Anything else is `Invalid`. Pin: `HL::test_record_field_types_and_bounds_are_enforced_on_read_and_publish`.
3. The notifier consumer, in one paragraph: `notifier_lock.py run` is the long-lived owner; it never `exec`s, it runs `task-notifier.sh` as its child with a control pipe, and lists that child, the watcher and each sender under `children`. Every spawn is reserve-then-spawn: the shell asks the owner over the pipe to reserve a named slot (`pending: true, reserved_at: now`), the owner writes it with `set_children`, the shell spawns, reports the pid, the owner records `pid` + `start_time(pid)` and clears `pending`; when the child exits the slot is removed. A successor's `acquire` therefore waits while a sender or watcher pid is live, treats a pending slot with no pid as live for 30 s and dead after, and fences the watcher through `authorize_signal(prior, "child:watcher", ...)`. No child ever holds fd 9; the fence that used to ride on the fd rides on the record. Pin (consumer): the notifier PR's `FirstActContract` subclass plus its own outlive and pending-slot tests.

## 3. Work root and first act

1. `acquire` creates nothing under the work root — not a file, not a directory; it creates only the lock directory (outside the work root, §5.1) and the lock file inside it. The work root need not exist. After `Acquired` the caller creates its own directories; before it, nothing. Pins: `HL::test_acquire_touches_nothing_under_the_work_root`, `HL::test_a_missing_work_root_still_acquires`.
2. "No trace" after any refusal (`Held`, `TimedOut`, `Unreadable`, `LockError`, or a fault between the flock and the return): the work root is byte-identical; in the lock dir only the lock file and other processes' `waiting.<pid>` files remain; the record is byte-identical. Pin: `HL::test_every_refusal_path_leaves_the_work_root_and_the_record_byte_identical`.
3. `tests/holder_lock_contract.py::FirstActContract`: a mixin driving a consumer's CLI argv through contention, no-trace, a missing root, a replaced lock file, and publish-before-spawn — between `acquire` and `publish` the caller starts no child that could act on the root (the fence's read-only `ps` is not such a child), so the record exists before any child can observe the root. The parent runs it against a stub; each consumer subclasses it per caller. Pins: `HL::test_the_first_act_contract_passes_against_the_stub_caller`, `HL::test_the_first_act_contract_pins_publish_before_any_child_is_spawned`.

## 4. Install boundary: the upgrader owns the order

1. `install_id()` is the install location only: `"<distribution>@<realpath of the package directory>"` (`dirname(ag2_sparrow.__file__)` resolved); the notifier's is `"sutando-src@<realpath of src/>"`. It is recorded and compared by `authorize_signal`; a same-location upgrade keeps it. No version is recorded. Pin: `HL::test_install_id_is_the_location_only`.
2. The upgrade order is stop → install → start, owned by the upgrader, not by this module. The real call sites: the keepawake self-upgrade (#5665), `ag2-sparrow-hatch install`, and the package installer script; each stops the package's adapters on the roots it launched, installs, then starts them. Those changes land in each call site's own PR; this module offers them nothing but `status`. A start while a live holder remains is `acquire`'s own `Held` — that is the whole of "check-install" now; nothing runs at install time. Pin (per call site, in its PR): `test_the_upgrader_stops_then_installs_then_starts`; here only `HL::test_a_start_against_a_live_holder_is_held_and_explains`.
3. Out of contract, stated plainly: there is no legacy pidfile read. A pre-`holder_lock` adapter is stopped by the upgrader before the new code runs. If one is somehow running (a violated order, a root the upgrader does not know, a by-hand start), its pidfile is ignored and nothing in this module detects it; the old binary's own `O_EXCL` check sees nothing of ours. The upgrade order is the control. Roots other than the ones the upgrader launched are out of scope: an adapter started by hand there still refuses a live holder of its own kind, nothing more. Pin: none (stated residual).

## 5. Lock location and filesystem

1. `lock_dir(work_root)`: `$SPARROW_LOCK_DIR` if set; else `$XDG_RUNTIME_DIR/ag2-sparrow/locks`; else `~/.local/state/ag2-sparrow/locks`; then `/<sha256(realpath(work_root))[:16]>`. Files inside: `lock`, `holder`, `waiting.<pid>`. The work root carries nothing lock-related, so no sync configuration is involved and a synced or cloud-mirrored work root is harmless to the lock. Pins: `HL::test_lock_dir_resolves_env_then_xdg_then_local_state_and_hashes_the_realpath`, `HL::test_two_paths_to_one_real_root_share_one_lock_dir`.
2. Local filesystem only, now trivially met by the resolver's defaults; `acquire` still raises `LockError("not a local filesystem")` when `statfs` reports a network or FUSE type for the lock dir (an override can point anywhere). Pin: `HL::test_a_network_or_fuse_lock_dir_is_refused` (mocked statfs).

## 6. Crash matrix (the owner killed at the boundary's end; the next start is the successor)

| After | Lock | Record | Successor |
|---|---|---|---|
| lock dir / file created, before flock | nobody | prior | reads prior; proceeds by its liveness |
| flock, before the prior read | kernel dropped | prior | same; the read is repeatable |
| prior read, before publish | dropped | prior | same; a caller that was fencing resumes from the same bytes |
| record temp written | dropped | prior + dot-temp | publish overwrites; the temp is a crash's own and is removed by `publish` |
| published, no children yet | dropped | ours (dead pid, `children: []`) | dead → `Acquired`, `prior = Valid(ours)` |
| a slot reserved, not yet spawned | dropped | ours + pending slot | `Held` until the slot is 30 s old, then dead |
| a child spawned and recorded, still running | dropped | ours + live slot | `Held(reason="child:<name>")`; `wait` polls until it exits |
| serving, all children exited | dropped | ours | dead → `Acquired` |
| clean exit, record removed, before close | held until close | none | `Held` for an instant, then `Acquired` with `prior = Missing` |

Pin: `HL::test_an_owner_killed_at_every_boundary_is_replaced_by_a_successor_whose_outcome_matches_the_row`.

## 7. Vendoring, tests, scope, merge order

1. `src/holder_lock.py` is canonical; `packages/ag2-sparrow/ag2_sparrow/holder_lock.py` is generated by one entry in `packages/ag2-sparrow/tools/sync_from_src.py`, never hand-edited; byte identity is guarded by `tests/ag2-sparrow-drift.test.py` and `packages/ag2-sparrow/tools/test_no_drift.py`; `test_wheel_contents.py` gains an installed-wheel import of `ag2_sparrow.holder_lock`. `tests/holder-lock.test.py` runs every `HL` case against both modules. Pin: `HL::test_every_case_runs_against_the_source_and_the_vendored_copy`.
2. The parent PR contains EXACTLY: the canonical module; its generated copy with the mapping entry; `file_lock.try_lock_fd`; the contract tests against both copies, with `holder_lock_contract.py` and its stub; this doc with its `docs/README.md` index entry and `docs/catalog.json` metadata; `docs/src-map.md` regenerated. No consumer, installer, sync or config change.
3. Merge order, final: prerequisite → #5660 → #5629. The prerequisite is a technical dependency of both; #5660 before #5629 is rollout priority (the production adapters' double-acquire race lands first; the notifier's queue delivery is opt-in). Each consumer rebases independently on the prerequisite.
