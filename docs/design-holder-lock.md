# holder_lock: the one flock-and-holder primitive (parent PR, design v3.3)

v3.3 adds (G): a legacy pidfile naming a live pid at this install's location is a same-install predecessor — held and waited for, passing `check-install` — so an unattended upgrade from a pidfile-only version is never refused (§4.4, §4.5). v3.2 folds the second reviewer's six amendments on v3/v3.1: (A) a record without an install id is `Invalid` and, when live, refuses like a foreign holder (§1.1); (B) the Hatch installer and the keepawake `target_version` auto-upgrade follow the same self-upgrade order (§4.5); (C) the old pidfile-only Codex connector can only come from a second install, which `check-install` refuses (§4.6); (D) a lease publishes once and releases only from its minting pid (§1.3–1.4); (E) an inherited fd re-enters across an in-place version change but not from another location (§1.6); (F) publish before spawning anything is part of the first-act contract (§3.3).

Reviewed first; merged first. v3 is the install-boundary revision: no runtime legacy coexistence, no mirror machinery of any kind. One module, `src/holder_lock.py`, vendored byte-identical into the package; the two consumer PRs are thin owners over it. It folds both reviewers' findings: `acquire` mints an opaque lease that carries the predecessor state instead of destroying it; publication is a distinct operation on that lease; the API carries the ownership proof it promises and owns the signal-authorisation decision; mixed-version runtime coexistence is dropped in favour of a checked install boundary; the pre-lease writes are named exactly; the module is POSIX-only by requirement. Test class: `HL` = `tests/holder-lock.test.py::HolderLockTest`, parametrised over the source and the vendored copy.

## 1. API

1. `acquire(path, *, install_id, timeout=0.0, on_replaced="refuse", legacy_pidfile=None) -> Lease | Held | TimedOut | ForeignInstall | Inconsistent | LegacyOwnerPresent`. Publishes NOTHING. `Lease` (opaque, single-use, not picklable across `exec`; `lease_from_inherited_fd` is the re-entry, §1.6) carries `fd`, `path`, `lock_id=(dev, ino)` of the file now at `path`, `generation` (the prior record's generation + 1, or 1), `install_id`, and `prior: Prior`. `Prior` is one of `Missing`, `Valid(record)`, `Invalid(reason, raw_bytes)`; it is read under the flock, after the flock is granted, never before. `Held(holder)` / `TimedOut(holder)`: another description holds the lock; `holder` is the current `read_holder`. `ForeignInstall(holder, reason)` and `Inconsistent(holder, reason)`: §4.2–4.3. A `Valid`-shaped record with NO `install_id`, or one that does not parse as an install id, is `Invalid`; when such an `Invalid` prior names a pid whose `verify_lineage` is True on this host, the lease is REFUSED — `ForeignInstall(holder, reason="record without install id")` — exactly like a live foreign holder, never granted (an `Invalid` prior naming no live pid proceeds and is moved aside on publish, §1.3). `LegacyOwnerPresent(pid | None, path)`: §4.4. Non-contention errors raise `LockError(reason)`: a directory or symlink at `path` (`O_NOFOLLOW`), `EACCES`, a replaced path under `on_replaced="refuse"` (`"reopen"` closes and reopens, the deadline preserved), an unsupported platform (§1.9). On any refusal after the flock was granted, the module unlocks and closes before returning, having written nothing but the lock file's own creation and the sidecar it removed. Pins: `HL::test_acquire_publishes_nothing_and_returns_the_prior_under_the_flock`, `HL::test_prior_distinguishes_missing_valid_and_invalid_bytes`, `HL::test_an_invalid_prior_naming_a_live_pid_refuses_like_a_foreign_holder` (no install id; an unparseable one; each with a live and a dead pid), `HL::test_acquire_returns_held_or_timed_out_and_never_two_leases`, `HL::test_a_replaced_path_is_refused_or_reopened_by_the_callers_choice`, `HL::test_a_directory_symlink_or_unwritable_path_raises_lock_error_and_creates_nothing`.
2. `wait(path, *, install_id, deadline, poll=0.1, on_tick=None, on_replaced="refuse", legacy_pidfile=None)`: same results minus `Held`; `deadline` is an absolute `time.monotonic()` value; `on_tick(elapsed_s, holder)` is called once per poll and may raise to abandon the wait. The sidecar `path + ".waiting"` holds `"<pid> <nonce> <epoch>\n"` where `nonce` is a per-call random token, so two waits in one process never overwrite or clear each other; it is removed only by the call whose nonce it carries. Pins: `HL::test_wait_publishes_and_clears_only_its_own_sidecar_by_nonce`, `HL::test_wait_calls_on_tick_with_elapsed_and_the_current_holder_and_honours_an_absolute_deadline`, `HL::test_the_deadline_survives_a_reopen`.
3. `publish(lease, record) -> Published(record)`: the one way a record reaches disk. Verifies the lease is unreleased, `same_file(lease.fd, lease.path)`, and `lease.lock_id` still matches; fills `schema`, `pid`, `start`, `host`, `lock`, `generation`, `install_id`, `acquired_at`; validates the caller's fields and `extra` (§2.2); writes by unique dot-temp + fsync + `os.replace`; an `Invalid` prior is first moved aside to `path + ".holder.invalid.<generation>"` (evidence preserved byte-for-byte), a `Valid` prior is replaced. Failure raises `LockError`, nothing written, the lease still valid. A lease publishes ONCE: a second `publish` on the same lease raises `LockError("published")` and writes nothing — a later change to `extra` is made through a fresh lease from `lease_from_inherited_fd` (§1.6), never by republishing. A non-blocking re-lock is NOT used as proof that an fd holds the lock: it acquires an unlocked fd (measured by the reviewer), so the existing `notifier_lock.holds()` that relies on it is a defect this module replaces. Pins: `HL::test_publish_fills_identity_fields_and_validates_the_callers`, `HL::test_publish_is_once_per_lease`, `HL::test_publish_moves_an_invalid_prior_aside_and_replaces_a_valid_one`, `HL::test_publish_refuses_a_released_lease_a_closed_fd_or_a_replaced_file`.
4. `release(lease) -> Released(record_removed: bool)`: removes `.holder` only if `same_file` holds and the record on disk names this `pid`, `generation` and `lock_id`; then unlocks and closes; the lease is dead afterwards and a second call raises `LockError("released")`. The lease records the pid that minted it; `release` from any other pid — a forked child in particular — raises `LockError("not the lease owner")` before touching anything, so the child's exit cannot `LOCK_UN` the parent's lock or remove its record (the child's copy of the fd closes on its exit without affecting the parent's description). The lock file itself is never unlinked, truncated, renamed or replaced by any function here. Pins: `HL::test_release_removes_only_its_own_record_then_unlocks_and_is_single_use`, `HL::test_release_from_a_forked_child_is_refused_and_the_parents_lock_stays` (a real `os.fork`: the child calls `release`, exits; the parent's probe still reports busy and its record is intact), `HL::test_nothing_in_the_module_unlinks_or_replaces_the_lock_file`.
5. `read_holder(path) -> Prior` (the same three-way type). `Invalid` covers missing fields, wrong types or bounds (§2.2), unsupported `schema`, torn JSON, a non-object. No caller may treat `Invalid` or `Missing` as "free": the flock decides acquisition; a record decides only what may be signalled. Pin: `HL::test_read_holder_never_raises_and_classifies_every_malformed_shape_as_invalid`.
6. `lease_from_inherited_fd(fd, path, *, install_id) -> Lease`: re-entry for a process that inherited the holder's fd (the notifier after `exec`, its `spawn` helper on fd 9). Proof, all required: `same_file(fd, path)`; a fresh probe fd on `path` reports busy through `file_lock.try_lock_fd` (someone holds the lock); `read_holder` is `Valid`, its `lock` equals `fstat(fd)`, its `install_id` equals ours, and its `pid` is this process or an ancestor of it (walking `ps -o ppid=`) with `verify_lineage` True. Any miss raises `LockError`. The lease it mints carries `generation` from the record and `prior = Valid(that record)`. Because `install_id` is the install LOCATION (§4.1), the equality check holds across an in-place version change: a notifier re-exec'd, or a helper started, after the package or `src/` was updated at the same path re-enters normally on the inherited fd; an fd whose record names a different location is still `LockError` (the record was written by another install). Pins: `HL::test_an_inherited_fd_is_proven_by_file_identity_busy_probe_and_ancestor_lineage`, `HL::test_an_inherited_fd_on_the_wrong_file_or_a_foreign_record_is_refused`, `HL::test_an_inherited_fd_re_enters_after_an_in_place_version_change_but_not_from_another_location`.
7. `authorize_signal(lease, target, *, argv_predicate=None) -> Authorized(pid) | Denied(reason)`: the complete decision, owned here so no consumer duplicates it. `target` is a dict with `pid`, `start` and optional `argv`; authorised only when: the record the target came from is `Valid` with a supported `schema`, its `host` equals the local host label, its `lock` equals `lease.lock_id`, its `install_id` equals ours, `verify_lineage(pid, start, host)` is True (None is `Denied("unobserved")`), and, when given, `argv_predicate(live argv of pid)` is True. A bare pid is never enough. Pins: `HL::test_authorize_signal_requires_schema_host_lock_identity_install_lineage_and_argv`, `HL::test_a_foreign_host_install_or_unobserved_lineage_is_denied`.
8. `same_file(fd, path) -> bool`; `verify_lineage(pid, start, host=None) -> bool | None` (None = unobserved, never a default); `start_time(pid) -> str | None` (`ps -o lstart=`, C locale, UTC, normalised); `install_id() -> str` (§4.1). Pins: `HL::test_same_file_rejects_a_replaced_or_missing_path`, `HL::test_verify_lineage_is_tri_state_and_rejects_a_recycled_pid`, `HL::test_start_time_ignores_locale_and_time_zone`.
9. Platform and `file_lock.py`: `holder_lock` builds on `file_lock` and this PR adds one typed function there, `try_lock_fd(fd) -> bool` (True acquired, False busy — the POSIX `EWOULDBLOCK` mapped once, in `file_lock`, not in the holder); it does not use `locked_file` (mkdirs the parent, blocks, unlocks on exit). The contract is POSIX-only: Linux and macOS, the two CI runners. On Windows every entry point raises `LockError("unsupported platform: holder_lock is POSIX-only")` at first use; no portability claim is made, and the package's adapters that use it are declared POSIX-only. The suite is added to the Windows job's manual test list, where it executes and asserts exactly that refusal. Pins: `HL::test_holder_lock_locks_only_through_file_lock`, `HL::test_try_lock_fd_returns_busy_instead_of_raising` (in `tests/file-lock.test.py`), `HL::test_on_windows_every_entry_point_raises_lock_error` (runs for real on the Windows job).

## 2. Holder record

1. `<path>.holder`, JSON: `{"schema": 1, "adapter": str, "pid": int, "start": str, "host": str, "lock": {"dev": int, "ino": int}, "generation": int, "install_id": str, "acquired_at": float, "extra": object}`.
2. Validation: `pid`, `dev`, `ino`, `generation` are `int` and not `bool`, `pid > 0`, `generation >= 1`; `start`, `host`, `adapter`, `install_id` are non-empty `str` ≤ 512 bytes; `acquired_at` is a finite `float`; `extra` is a JSON object ≤ 64 KiB whose nested `pid`/`start` fields, where present, obey the same rules. Anything else is `Invalid`. Pin: `HL::test_record_field_types_and_bounds_are_enforced_on_read_and_publish`.
3. Nothing in the record authorises acquisition. A record authorises a signal only through `authorize_signal` (§1.7). Pin: `HL::test_no_code_path_reads_a_record_to_decide_acquisition` (spy).

## 3. Work root and first act

1. Writes that precede a `Lease`, exactly: the caller's `os.makedirs(root, exist_ok=True)` of the work root itself; the lock file's own `O_CREAT` at `<root>/<name>`; the `.waiting` sidecar beside it during a `wait`, removed before return. Nothing else: no directory under the root is created before the `Lease` — that is the first-act contract. A legacy pidfile under a not-yet-existing `state/` reads as absent. Pins: `HL::test_only_the_root_the_lock_file_and_the_sidecar_exist_before_a_lease`, `HL::test_a_truly_empty_root_acquires_and_creates_nothing_else`.
2. "No trace" after any refusal (`Held`, `TimedOut`, `ForeignInstall`, `Inconsistent`, `LegacyOwnerPresent`, `LockError`, or a fault between the flock and the return): nothing exists under the root except the lock file and whatever existed before; a record this call did not write is byte-identical; the sidecar is gone. The lock file may remain after a refusal on a first start — it is a permanent artifact, stated, and never removed. Pin: `HL::test_every_refusal_path_leaves_the_root_byte_identical_except_the_lock_file` (snapshot before/after, parametrised over each path with an injected fault).
3. `tests/holder_lock_contract.py::FirstActContract`, a mixin driving a consumer's CLI argv through contention, no-trace, a missing root, an empty root, a replaced path, a foreign install, the legacy refusal, and publish-before-spawn: between `acquire` and `publish` the caller starts no child process that could act on the root (no watcher, sender, provider or helper), so the record exists before any child can observe the root; the read-only process-table queries a fence makes (`ps` through `verify_lineage`/`start_time`) are not such children. The parent runs the mixin against a stub caller; each consumer subclasses it per caller. Pins: `HL::test_the_first_act_contract_passes_against_the_stub_caller`, `HL::test_the_first_act_contract_pins_publish_before_any_child_is_spawned` (a `fork`/`exec` spy between the two calls fails the stub; `ps` is allowed).

## 4. Install boundary (replaces runtime legacy coexistence)

1. Mixed versions on one work root are not made safe at runtime. The adapters ship in one package and one venv, so an upgrade replaces the old code; two versions on one root happen only through two installs, and that is refused, not tolerated. `install_id()` is the install LOCATION, not the version: `"<distribution>@<realpath of the package directory>"` (`dirname(ag2_sparrow.__file__)` resolved; the repo-side notifier uses `"sutando-src@<realpath of src/>"`). The version is recorded beside it in the holder record as `version` for diagnostics only and never compared: a package upgraded in place into the same venv is the same install, so a still-running pre-upgrade adapter is an ordinary predecessor (live → the successor waits or refuses as a holder, never as a foreign install; dead → replaced on publish). Pin: `HL::test_install_id_is_the_location_and_ignores_the_version`.
2. At `acquire`, after the flock: a `Valid` prior whose `install_id` differs from ours and whose pid has `verify_lineage` True → unlock, `ForeignInstall(holder)`; the caller exits 3 "stop the adapter from <install_id> (pid N), then start". A `Valid` prior from another install naming a dead pid is an ordinary dead predecessor and is replaced on publish. Pins: `HL::test_a_live_holder_from_another_install_refuses_naming_it`, `HL::test_a_dead_holder_from_another_install_is_replaced`.
3. A `Valid` prior from our own install whose pid has lineage True while we hold the flock is impossible for a correct holder (it would hold the lock); it is `Inconsistent(holder, "live record without the lock")` → unlock, caller exits 2 for the operator; the record is preserved. Pin: `HL::test_a_live_record_that_does_not_hold_the_lock_is_inconsistent_and_preserved`.
4. The one legacy refuse-and-explain path: when `legacy_pidfile` is given, read it ONCE after the flock. Exactly one positive integer naming a live pid other than ours: resolve that process's location — the realpath of its executable's prefix and of the package directory in its argv/cwd (`ps -o command=` plus `/proc/<pid>/exe` on Linux, `proc_pidpath` via `ps -o comm=` on macOS) — and when it resolves under THIS install's location it is a same-install predecessor from before holder_lock: `acquire` returns `Held(legacy=pid)` (a plain live holder; `wait` keeps polling until it exits), never a refusal; when it resolves elsewhere or cannot be resolved → unlock, `LegacyOwnerPresent(pid, path)`; the caller exits 3 "stop the old adapter (pid N), then start". Anything else that is not absent or a single dead pid (empty, partial, several lines) → `LegacyOwnerPresent(None, path)`; the caller exits 3 "<path> is not a pid record; stop the old adapter and remove it, then start" — an empty file may be an old binary between its `O_EXCL` and its write, so it is never taken. Absent or a single dead pid → proceed; after `publish`, the lease holder removes that dead leftover under the flock (`publish` does it, logged). The new code never writes the legacy file; there is no mirror, no `mirror_names_me`, no N+1 cleanup. Pins: `HL::test_a_live_legacy_pid_at_this_location_is_held_and_waited_for_not_refused`, `HL::test_a_live_legacy_pid_elsewhere_or_unresolvable_refuses_naming_it`, `HL::test_a_malformed_or_empty_legacy_file_refuses_naming_the_file`, `HL::test_a_dead_legacy_leftover_is_removed_after_publish_under_the_flock`, `HL::test_nothing_in_the_module_writes_the_legacy_pidfile`.
5. The install step checks the boundary too: the package installer (and the repo's engine update) runs `python -m ag2_sparrow.holder_lock check-install <work root>...` for every configured work root; a `Valid` record naming a live pid from an install other than the one being written, or a legacy pidfile naming a live pid that does not resolve under the location being written, refuses the install with exit 3 and the same explanation; a legacy pidfile naming a live pid AT that location (an adapter from before holder_lock, upgraded in place) passes `check-install`, and the stop step that follows ends it, so the one transition every existing agent makes — an unattended keepawake upgrade from a pidfile-only version — is never refused. Pin (added): `HL::test_an_unattended_upgrade_from_a_pidfile_only_adapter_at_the_same_location_passes_check_install_then_stops_and_starts`. Documented as the upgrade step: stop every adapter on the root, install, start. An in-place self-upgrade that installs the new version into the SAME venv is the same install — the Hatch installer, the keepawake unattended upgrade to `target_version`, and the repo's engine update are all callers of one order: install → `check-install` (passes, same location) → stop the package's adapters → start them. Since 33864e8 made the id location-based, an in-place version change is never a foreign install, so no unattended upgrade refuses on its own running adapter; the new adapter then acquires once the old one has released, and a self-upgrade that starts the new adapter before stopping the old one gets the ordinary live-holder refusal (exit 3 naming the pid), not a wedge. Pins (added): `HL::test_a_same_location_upgrade_passes_check_install_while_the_old_adapter_runs`, `HL::test_every_installer_entry_point_runs_check_install_then_stop_then_start` (the Hatch installer, the keepawake upgrade and the engine update, each as a scripted stand-in), `HL::test_a_new_version_at_the_same_location_waits_for_the_old_holder_not_a_foreign_refusal`. Pins: `HL::test_check_install_refuses_a_live_foreign_or_legacy_holder_and_passes_otherwise`, `HL::test_the_doc_states_the_upgrade_step` (doc scan).
6. What is deliberately not covered: an old binary that ignores the flock and is started after the boundary check (by hand, from a second install). It is a violated prerequisite; the refusal messages name it, `status` reports it, and a health check surfaces an exit-3 loop. Pin: `HL::test_status_reports_a_legacy_or_foreign_holder` (status only). The old pidfile-only Codex connector in particular can start after the single legacy read of §4.4 and never see the new holder; that is prevented by where it can come from, not by a second read: the package ships all three adapters, so a same-location upgrade replaces the connector's code too, and the only way an old connector exists at all is a second install — the violated prerequisite that `check-install` refuses when its pidfile names a live pid (§4.5) and that `status` and the health check surface otherwise. Pin: `HL::test_an_old_connector_can_only_come_from_a_second_install_which_check_install_refuses` (a second-install stand-in with the old `O_EXCL` writer: `check-install` exit 3 while it runs; `status` names it after a start that bypassed `check-install`).

## 5. Filesystem and sync requirements

1. Local filesystem only. `flock` is per kernel: on NFS, SMB and FUSE mounts it is emulated per client or absent, so two hosts (or one host through two mounts) can both hold `LOCK_EX`; cloud-sync agents replace files by rename, which changes `(dev, ino)` under a holder. `acquire` raises `LockError("not a local filesystem")` when `statfs`/`statvfs` reports a network or FUSE type on the supported hosts. Pin: `HL::test_a_network_or_fuse_filesystem_is_refused` (mocked statfs).
2. `.lock`, `.lock.holder`, `.lock.holder.invalid.*`, `.lock.waiting`, `.adapter.lock*`, `connector.pid` and their dot-temps are added to the default `vault.sync.exclude` in `sutando.config.json`; `sync-workspace.sh` emits explicit denies over `vault.sync.include`, so including `state/` still never syncs a lock. Pin: `tests/sutando-config.test.py::VaultSyncDefaultsTest::test_the_default_exclude_list_names_every_lock_record_and_sidecar`.

## 6. Crash matrix (the holder killed at the boundary's end; the next start is the successor)

| After | Lock | On disk | Successor |
|---|---|---|---|
| open, before flock | nobody | prior | lease with that `prior`; the caller fences from it, then publishes |
| flock, before the prior read | kernel dropped | prior | same; the read is repeatable |
| prior read, before legacy / install check | dropped | prior | same |
| caller fencing, before publish | dropped | prior (its target now dead) | `prior` unchanged; `authorize_signal` denies (lineage False); publishes |
| record temp written | dropped | prior + dot-temp | publish replaces; the temp is a crash's own temp |
| record replaced (generation g) | dropped | ours (dead pid) | lease `prior = Valid(ours)`, generation g+1; nothing authorised; replaced |
| dead legacy leftover removed | dropped | ours | same |
| serving | dropped | ours | same |
| clean exit, record removed, before close | held until close | none | `Held` for an instant, then a lease with `prior = Missing` |

Pin: `HL::test_a_holder_killed_at_every_boundary_is_replaced_by_a_successor_whose_prior_matches_the_row`.

## 7. Vendoring, tests, scope, merge order

1. `src/holder_lock.py` is canonical; `packages/ag2-sparrow/ag2_sparrow/holder_lock.py` is generated by one entry in `packages/ag2-sparrow/tools/sync_from_src.py`, never hand-edited. Byte identity is guarded by the existing `tests/ag2-sparrow-drift.test.py` and `packages/ag2-sparrow/tools/test_no_drift.py`; `test_wheel_contents.py` is extended with an installed-wheel runtime import of `ag2_sparrow.holder_lock` (not only archive membership). `tests/holder-lock.test.py` runs every `HL` case against both modules (`subTest(module=...)`). Pin: `HL::test_every_case_runs_against_the_source_and_the_vendored_copy`.
2. The parent PR contains EXACTLY: the canonical module; its generated copy with the mapping entry; `file_lock.try_lock_fd` (the one `file_lock.py` change, §1.9); the contract tests against both copies, with `holder_lock_contract.py` and its stub; the Windows-job manual-list entry; the `vault.sync.exclude` defaults and their test (§5.2); the `check-install` entry point; one doc page (this contract plus the upgrade step) with its `docs/README.md` index entry and `docs/catalog.json` metadata so `docs_audit.py` passes; `docs/src-map.md` regenerated. No consumer call-site change, no adapter or notifier code, no change to `task_io`, `task_lifecycle` or `task-notifier.sh`.
3. Merge order, final: prerequisite → #5660 → #5629. The prerequisite is a technical dependency of both consumers; #5660 before #5629 is rollout priority, not a stack dependency — #5660 carries the fix for the double-acquire race in the `acquire_lock` the routine and Codex adapters run in production today, #5629's queue delivery is opt-in. Each consumer rebases independently on the prerequisite.
