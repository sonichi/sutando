# holder_lock: the one flock-and-holder primitive (parent PR, design v1)

Reviewed first; merged first. One module, `src/holder_lock.py`, vendored byte-identical into the package; two consumer PRs become thin owners over it, in the order holder_lock → the adapter PR → the notifier PR. The reviewer's objections this answers: two prospective owners of one primitive, a pid file used as a lock, an unstated work-root rule, an incomplete wait contract, and a legacy interlock that did not fence old binaries. Test class: `HL` = `tests/holder-lock.test.py::HolderLockTest`. Stdlib only, built on the existing `file_lock.lock_fd(fd, blocking=False)` / `unlock_fd` so the package's OS-independent contract holds (see §1.9).

## 1. API

1. `acquire(path, *, timeout=0.0, on_replaced="refuse", legacy_pidfile=None, record=None) -> Acquired | Held | TimedOut | LegacyOwnerPresent`. One attempt when `timeout == 0`; otherwise a bounded poll (0.1 s) until `timeout` elapses, the deadline fixed once and preserved across a reopen. `Acquired(fd, record)`: the caller holds `LOCK_EX` on the file now at `path`, the holder record is published (`record` is the caller's fields, §2), and, when `legacy_pidfile` is given, the mirror is written (§4). `Held(holder)`: another description holds it; `holder` is `read_holder(path)` (None when unreadable). `TimedOut(holder)`: the same after `timeout`. `LegacyOwnerPresent(pid, path)`: §4. Errors that are not contention raise `LockError(reason)`: a directory or symlink at `path` (`O_NOFOLLOW`), `EACCES`, or a replaced path under `on_replaced="refuse"`; `on_replaced="reopen"` closes and reopens instead. Pins: `HL::test_acquire_returns_acquired_held_or_timed_out_and_never_two_acquired`, `HL::test_a_replaced_path_is_refused_or_reopened_by_the_callers_choice`, `HL::test_a_directory_symlink_or_unwritable_path_raises_lock_error_and_creates_nothing`.
2. `wait(path, *, deadline, poll=0.1, on_tick=None, on_replaced="refuse", legacy_pidfile=None, record=None) -> Acquired | TimedOut | LegacyOwnerPresent`: the loop behind `timeout > 0`, exposed so a caller can own its wording. While waiting it publishes `path + ".waiting"` as `"<pid> <epoch>\n"` by temp + replace, calls `on_tick(elapsed_s, holder)` each poll (the caller logs on its own cadence), and removes the sidecar only if it still names this pid. No module but this one writes the sidecar; read-only consumers (a health check) may read it. Pins: `HL::test_wait_publishes_and_clears_only_its_own_sidecar`, `HL::test_wait_calls_on_tick_with_elapsed_and_the_current_holder`, `HL::test_the_deadline_survives_a_reopen`.
3. `publish_holder(path, record) -> None`: writes `path + ".holder"` as JSON by unique dot-temp + fsync + `os.replace`. The caller must hold the flock on `path`; the function verifies it (`same_file` + a non-blocking re-lock on the caller's fd) and raises `LockError` otherwise. Pin: `HL::test_publish_holder_is_atomic_and_refuses_a_non_holder`.
4. `read_holder(path) -> dict | None`: None for a missing, empty, partial, non-JSON, non-object, unsupported-`schema` or field-incomplete record. None means "held by someone whose record cannot be trusted" for every decision; no caller may treat None as "free". Pin: `HL::test_read_holder_returns_none_for_every_malformed_shape_and_never_raises`.
5. `same_file(fd, path) -> bool`: `fstat(fd)` and `stat(path)` agree on `(st_dev, st_ino)`. Pin: `HL::test_same_file_rejects_a_replaced_or_missing_path`.
6. `verify_lineage(pid, start, host=None) -> bool | None`: True when `pid` is alive on this host and its normalised start time equals `start` and, when `host` is given, equals the local host label; False when any differs; None when the process table could not be consulted — never a default, carried to the caller undecided. Pin: `HL::test_verify_lineage_is_tri_state_and_rejects_a_recycled_pid`.
7. `release(fd, path, *, remove_record=True)`: removes `.holder` only if it names this pid and this lock identity, removes the mirror only if it names this pid (§4.6), then closes `fd`; the lock file itself is never unlinked, truncated, renamed or replaced by any function here. Pin: `HL::test_release_removes_only_its_own_record_and_mirror_and_never_the_lock_file`.
8. `start_time(pid) -> str | None`: `ps -o lstart=` in C locale and UTC, whitespace-normalised; None when unobservable. Shared by every record writer and `verify_lineage`. Pin: `HL::test_start_time_ignores_locale_and_time_zone`.
9. Relation to the existing portable `file_lock.py`: `holder_lock` builds ON it — it imports `lock_fd(fd, blocking=False)` and `unlock_fd` and adds nothing platform-specific of its own — but it does not use `locked_file`, because that context manager creates the parent directories (forbidden by the first-act rule, §3), blocks unconditionally, and unlocks on exit, whereas a holder's fd must stay locked across `exec` and be released only by `release` or the kernel. `(dev, ino)` identity uses `os.stat`, which populates `st_ino` on Windows; `verify_lineage` and `start_time` return None on Windows, so nothing is ever authorised there, and `read_holder`/`publish_holder` still work. Pins: `HL::test_holder_lock_locks_only_through_file_lock` (source scan: no `fcntl`/`msvcrt` import in `holder_lock.py`), `HL::test_on_windows_nothing_is_authorised_but_records_still_round_trip` (skipped off-Windows; the mocked variant runs everywhere).

## 2. Holder record

1. `<path>.holder`, JSON: `{"schema": 1, "adapter": <caller name>, "pid", "start", "host", "lock": {"dev", "ino"}, "acquired_at", "extra": {}}`. `extra` is the caller's own object (the notifier keeps its watcher there); the primitive validates only its own fields.
2. What each field authorises. Nothing in the record authorises acquisition — the flock does. A caller may signal a pid named in a record (its own or `extra`'s) only when all of these hold: `schema` is supported; `host` equals the local host label; `verify_lineage(pid, start, host)` is True; `lock.dev/ino` equals `fstat` of the lock fd the caller holds now. The last proves the record was written by a holder of this very file, not copied from another workspace or left by a replaced file. A record failing any one authorises nothing and is left byte-for-byte. Pins: `HL::test_a_signal_is_authorised_only_when_pid_start_host_and_lock_identity_all_match`, `HL::test_a_foreign_host_or_unsupported_schema_record_authorises_nothing`.
3. Written only by the holder, immediately after the flock (and after the legacy veto, §4), before any other write under the work root. Rewritten by the holder whenever `extra` changes; removed by the holder on clean exit before close. Pin: `HL::test_the_record_is_written_after_the_veto_and_before_anything_else`.

## 3. Work root and first act

1. The lock file lives at the work root: `<work>/<name>` (the adapter PR uses `.adapter.lock`; the notifier uses `state/codex-notifier.lock` with `<workspace>/state` as its root). The root must exist before `acquire`: a caller that owns the root does `os.makedirs(root, exist_ok=True)` first — creating the root is not writing under it — then calls `acquire`. Nothing under the root (`tasks/`, `results/`, `state/`) is created before `Acquired`. This deliberately changes the three adapters' current direct-CLI behaviour (they create the directories first). Pins: `HL::test_a_caller_creates_only_the_root_before_acquire`, and the first-act contract of §3.3.
2. A process that gets `Held`, `TimedOut`, `LegacyOwnerPresent` or `LockError` has created nothing under the root: the lock file already existed (the holder made it) or was not created (`LockError` before open), the sidecar is removed, no record, no mirror. Pin: `HL::test_a_refused_process_leaves_no_trace_under_the_root`.
3. The parent ships `tests/holder_lock_contract.py::FirstActContract`, a mixin that drives a consumer's CLI argv through contention, no-trace, a missing root, a replaced path and the legacy veto, so each consumer pins all its callers with the same cases (the adapter PR subclasses it three times; the notifier once). The parent runs it against a stub caller. Pin: `HL::test_the_first_act_contract_passes_against_the_stub_caller`.

## 4. Mixed-version legacy veto (one release)

1. One order, inside `acquire`, after the flock and before the record: if `legacy_pidfile` is given, read it ONCE. Exactly one line, an integer pid, alive on this host and not ours → `release` the flock (no record written) and return `LegacyOwnerPresent(pid, path)`; the caller exits 3 naming it. Absent, or a single dead pid → proceed: publish the record, then write the mirror (§4.2). Anything else (empty, partial, non-integer, several lines, our own pid left by a crash of a same-pid ancestor) → release and return `LegacyOwnerPresent(None, path)`; the caller exits 3 naming the file for the operator. Pins: `HL::test_the_legacy_veto_runs_after_the_flock_and_before_the_record`, `HL::test_a_live_legacy_pid_vetoes_and_a_dead_or_absent_one_does_not`, `HL::test_a_malformed_legacy_pidfile_vetoes_naming_the_file`.
2. The mirror: the new owner writes `legacy_pidfile` as `"<pid>\n"` BEFORE serving, under the flock. Absent → write a temp and `os.link(temp, path)`; `EEXIST` means an old binary created it meanwhile: re-read once; a live pid not ours → release, `LegacyOwnerPresent`; else `os.replace(temp, path)`. Dead pid present → `os.replace(temp, path)`. An old binary that starts after this sees a live pid in its stale check and refuses, and its `O_EXCL` create fails. Pins: `HL::test_an_absent_mirror_is_taken_by_link_and_an_eexist_rereads`, `HL::test_an_old_binary_starting_after_the_mirror_refuses` (a real old-binary stand-in using the O_EXCL+unlink logic).
3. The remaining window, named: an old binary that read a dead pid and is paused before its unconditional unlink while the new owner publishes its mirror. The old binary resumes, unlinks the live mirror, creates its own and starts. One-release mitigation: before each provider call the new owner calls `mirror_names_me(legacy_pidfile) -> bool` (part of the API: True only when the file is exactly `"<our pid>\n"`; a read error is False) and exits 3 ("legacy owner replaced the mirror") on False, stopping before the call. Both never serve concurrently beyond one provider call boundary; the old binary wins. Pin: `HL::test_the_stale_read_unlink_race_ends_with_exactly_one_server` (real old-binary stand-in paused at its unlink; outcome: one serves, the other exits 3, the mirror names the survivor).
4. The same race against the primitive without an old binary (two new owners): impossible, the flock serialises them; pinned anyway. Pin: `HL::test_two_new_owners_over_a_stale_record_yield_exactly_one_acquired_and_one_held`.
5. Clean exit: the owner removes its mirror, then its record, then closes the flock. An old binary starting in between may start, but the exiting owner no longer serves (its last provider call preceded the mirror removal), so there is no overlap. Pin: `HL::test_a_clean_exit_removes_mirror_then_record_then_closes`.
6. Next release (N+1): the veto read and the mirror write stop. The allowlist for `state/` keeps `connector.pid` and its temps `.connector.pid.<pid>.<rand>.tmp` for one more transition; under the flock the holder removes a mirror naming a dead pid or a malformed one (there is no old binary left to race), and nothing else touches it. A mirror naming a live pid in N+1 is an old binary still running → exit 3. Pin: `HL::test_the_next_release_cleans_a_dead_or_malformed_mirror_under_the_flock_and_still_vetoes_a_live_one`.

## 5. Crash matrix (the holder killed at the boundary's end; the next start is the successor)

| After | Lock | Record / mirror on disk | Successor |
|---|---|---|---|
| open, before flock | nobody | prior | acquires; veto; publishes |
| flock, before the legacy read | dropped by the kernel | prior | same |
| legacy read, before record | dropped | prior | same; the read is repeatable |
| record temp written | dropped | prior + dot-temp | same; its publish replaces; the temp is a crash's own temp, cleared by the consumer's allowlist rule |
| record replaced, before mirror | dropped | ours | acquires; veto sees absent/dead; publishes; mirrors |
| mirror linked | dropped | ours + mirror naming a dead pid | veto: dead → proceed; mirror replaced |
| serving | dropped | ours (dead pid) + mirror (dead pid) | same |
| clean exit, mirror removed | still held until close | record only | `Held` for an instant, then acquires |
| clean exit, record removed, before close | held until close | none | same |

Pin: `HL::test_a_holder_killed_at_every_boundary_is_replaced_by_a_successor_that_reads_nothing_to_decide`, parametrised over the rows; the "reads nothing to decide" assertion spies `read_holder` and confirms it is not on the acquire path (the legacy read is the one stated exception, §4.1).

## 6. Vendoring and tests

1. `src/holder_lock.py` is canonical; `packages/ag2-sparrow/ag2_sparrow/holder_lock.py` is GENERATED by adding one entry to `tools/sync_from_src.py`'s map and is never hand-edited; the package's `test_wheel_contents.py` already fails on drift. The contract tests are parametrised over both modules the way the adapter PR's lifecycle tests are: `tests/holder-lock.test.py` loads `src/holder_lock.py` and the vendored copy in turn and runs every `HL` case against each (`subTest(module=...)`), so a copy that imports differently or drifts fails the same test. Pins: `test_wheel_contents` (existing), `HL::test_every_case_runs_against_the_source_and_the_vendored_copy` (asserts both parametrisations executed).
2. Every clause above names its `HL` test; the stale-read/unlink race (§4.3), the two-new-owners race (§4.4), the veto order (§4.1), the first-act contract (§3.3) and the wait results (§1.1–1.2) are the ones the reviewer asked for by name.

## 7. Scope of the parent PR

1. Contains EXACTLY: the canonical `src/holder_lock.py`; its generated vendored copy with the one `tools/sync_from_src.py` mapping entry; the integration with `file_lock.py` as stated in §1.9 (an import, no change to `file_lock.py`); and the contract tests of §6 run against both the source and the vendored copy, including `tests/holder_lock_contract.py` with its stub caller. Plus the mechanical `docs/src-map.md` regeneration the repo requires for a new `src/` module.
2. Does not contain: any consumer call-site change, any notifier or adapter code, any change to `task_io`, `task_lifecycle` or `task-notifier.sh`, and no behaviour change anywhere that runs today. Consumers rebase on it; an independent implementation of any function in §1 in a consumer is prohibited and pinned by each consumer's "no lock logic" source scan.

## 8. Merge order

1. Prerequisite (this PR) → the adapter PR (#5660) → the notifier PR (#5629). Reason: #5660 carries the fix for the double-acquire race in the `acquire_lock` that the routine and Codex adapters run in production today (two adapters mutating one work dir and sending duplicate provider turns), while #5629's queue delivery is an opt-in feature whose lock protects a path that is off by default. The production defect lands first.
2. The reviewer proposed the other order (#5629 before #5660). The order stays open if he still prefers it after this reason; nothing in either consumer note depends on which lands second, since both are thin owners over the same prerequisite.
